# 双端同步与移动端交互完善

> 日期：2026-08-16  
> 范围：Windows/Android Supabase 同步、云端回写刷新、Todo/Memo 手机输入与 Todo 空间优化

## 结论

- 同步仍采用原方案：Supabase 邮箱和密码登录；Windows 与 Android 使用同一账号，不接 QQ 登录。
- 本地写入继续先落 SQLite，再由 outbox 上传；单次同步会持续处理所有待上传批次，不再只处理首批 100 条。
- 云端拉取改为全量拉取后按 `revision + updated_at` 合并，避免设备时间偏差造成游标漏数据。
- 云端数据落库后增加第二轮父子关系修复，覆盖备忘录父级、子任务父级及 Todo/备忘录关联。
- 同步状态进入成功态后，当前 Todo 与 Memo 页面会主动刷新，不需要切换页面才能看到另一端的新数据。

## 移动端交互

- 宽度低于 900px 时，Todo 与 Memo 不再常驻底部输入栏，统一通过右下角新增按钮按需弹出创建流程。
- 手机创建结束后不再强制重新聚焦输入框，避免键盘反复弹出。
- Todo 小精灵移出筛选标题栏，改为右侧屏幕外半藏式浮层，不参与列表布局计算。
- 屏幕边缘精灵只占 100×145 的局部浮层，默认半露；对话向左展开，不压缩智能视图和分类栏。

## 同步边界

- 两端构建必须使用相同 `SUPABASE_URL`、`SUPABASE_ANON_KEY` 和 schema。
- 两端必须登录同一邮箱账号，RLS 才会把数据归入同一用户空间。
- 代码路径和静态检查已完成；真正的“Windows 写入 → Android 自动出现 → Android 修改 → Windows 回写”仍需要在两台实际设备上登录后验收，不能用单机测试代替。
