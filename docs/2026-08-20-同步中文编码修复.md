# 2026-08-20 同步推送中文编码修复

## 问题

小花先生反馈：双端邮箱登录成功，但手机点击"立即同步"提示"同步失败，修改已保存在本机"。

## 定位

1. Windows 端 SQLite（`%LOCALAPPDATA%\XiaohuaTodo\todo_list.db`）`sync_outbox.error_message` 记录了确切错误：

   ```
   Invalid argument (string): Contains invalid characters.:
   "[{\"user_id\":...\"content\":\"办一张visa卡\"...}"
   ```

   且 `attempt_count` 高达 95——**双端其实都从未同步成功过**，不只是手机。

2. 根因：`lib/sync/supabase_sync_gateway.dart` 的 `_headers` 里 `content-type: application/json` **没有 charset 参数**。dart:io 的 `HttpClientRequest` 按 content-type 的 charset 决定 body 编码，无 charset 时回退 latin1（ISO-8859-1）；payload 含中文时 `latin1.encode` 直接抛 `Contains invalid characters`，**请求根本没发出去**（本地异常，不是网络/RLS 问题）。

3. 登录不受影响的原因：`_authenticate`/`_refreshSession` 用的是 `request.headers.contentType = ContentType.json`（自带 `charset=utf-8`），且登录体是 ASCII。

## 修复

`lib/sync/supabase_sync_gateway.dart` `_headers`：

```dart
'content-type': 'application/json; charset=utf-8',
```

显式带 `charset=utf-8`，让 dart:io 用 utf8 编码 body。

> 踩坑记录：曾尝试 `request.encoding = utf8`（在 `_headers.forEach` 之后），但请求对象抛 `Bad state: IOSink encoding is not mutable`——body 编码在 content-type 设置后不可再改，必须从 header 源头带 charset。

## 测试

- 新增 `test/sync_gateway_encoding_test.dart`：起本地 `HttpServer`，`SupabaseSyncGateway.push` 发送含中文 payload（含 `±×÷` 特殊字符）的变更，断言服务器收到合法 utf8 JSON、中文完整。
  - 注意：该测试**不能**用 `TestWidgetsFlutterBinding`（flutter_test 会劫持 HttpClient，所有请求返回 400）。
- 全量测试 **29/29 通过**（28 原有 + 1 新增）。

## 影响

- 修复后首次同步会把双端积压的 `sync_outbox`（Windows 端数百条）按批次推送上去，正常合并。
- 手机端需重装新 APK；Windows 端需重跑 Release。
- `_pull`（GET 无 body）与 Realtime（WebSocket 文本帧）不受此 bug 影响。
