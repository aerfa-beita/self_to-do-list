# 2026-08-24 Android 提醒失效根因：R8 混淆丢泛型（Missing type parameter）

## 背景

小花先生验收 8/24 release 时反馈：
1. **手机"安排"模式设置提醒** → 弹出「提醒安排失败：PlatformException ... Missing type parameter.」完整错误堆栈（截图确认）
2. **备忘录设置提醒** → 不报错，但到点完全不提醒

## 根因（实锤）

手机截图（QQ 图片）经 MiMo 视觉分析提取完整堆栈：

```
PlatformException(error, Missing type parameter., null,
java.lang.RuntimeException: Missing type parameter.)
at com.dexterous.flutterlocalnotifications.FlutterLocalNotificationsPlugin
  .loadScheduledNotifications / saveScheduledNotification / zonedScheduleNotification
```

- `flutter_local_notifications` 18.0.1 内部用 **Gson `TypeToken`** 序列化 `ScheduledNotification`（含泛型 `NotificationDetails`）
- Android **release 构建默认开 R8 混淆**，把类文件里的**泛型签名（Signature）剥掉** → Gson 反射拿不到类型参数 → `Missing type parameter` → `zonedSchedule` 抛异常，**提醒根本没排进系统**
- debug 包不混淆所以一直正常；这是 release 包独有问题（与 8/17 提醒修复无关，修复在源码里没生效是因为没走到）
- Windows 端无此问题（无 R8）

### 为什么表现不一样

| 入口 | 代码 | 表现 |
|------|------|------|
| Todo/安排 | `todo_screen.dart` `_scheduleReminder` 检查返回值 + SnackBar | 看到「提醒安排失败」报错 |
| 备忘录 | `memo_screen.dart` `_scheduleMemoReminder` **不检查返回值** | 异常被吞 → "没报错但不提醒" |

**两个问题是同一根因**，只是错误可见性不同。

## 修复

### 1. 新增 `android/app/proguard-rules.pro`（R8 保留 Gson 泛型）

规则来自 flutter_local_notifications 官方 example（v19+ 已内置此修复，v18 必须手动加）：
- `-keepattributes Signature`（泛型签名）
- `-keepattributes *Annotation*`、`InnerClasses`
- TypeToken 及子类 keep
- TypeAdapter/TypeAdapterFactory/JsonSerializer/JsonDeserializer 接口保留
- `@SerializedName` 字段保留

### 2. `android/app/build.gradle.kts` release 块注册规则

```kotlin
proguardFiles(
    getDefaultProguardFile("proguard-android-optimize.txt"),
    "proguard-rules.pro",
)
```

### 3. `lib/screens/memo_screen.dart` 备忘录补失败反馈

`_scheduleMemoReminder` 检查 `scheduleReminder` 返回值，false 时 SnackBar 提示「提醒安排失败：<status.message>」，与 Todo 侧一致，杜绝静默失败。
