# 2026-08-25 备忘录子树级联转 Todo(修复子层级不被关联)

## 背景

小花先生从备忘录发起"转为 Todo / 按行生成 / 关联已有 Todo"时,只有被点击的那一条备忘录被处理,**子备忘录完全不参与**。实际案例:备忘录"英语六级650分"下有子备忘录(听力、词汇等),转为 Todo 后生成的 Todo 里没有任何子任务。

**根因**:`lib/services/task_memo_service.dart` 三个方法只接收单个 `Memo` 对象,从不递归查询子备忘录。`memos` 表是邻接表(`parent_id` 指向父行),子备忘录是独立行;`MemoService.getChildren` 只在 UI 树展开时被调用,关联路径从未触碰。

**方案确认**(与小花先生逐条确认):
1. **转为 Todo**:父备忘录生成 1 个 Todo;所有子孙备忘录按原层级转成 **SubTask 树**挂在该 Todo 下(层级不变)。父 Todo ↔ 父备忘录保持 `task_memo_links` 关联;子备忘录与 SubTask 之间不建关联表
2. **按行生成**:**有子备忘录时不拆行**,整体转成 1 个 Todo + 子任务树;无子备忘录时保持现状按行拆平铺 Todo(拆行仅适用于无子级的清单式备忘录)
3. **关联已有 Todo**:级联——选中 Todo 后,父备忘录 + 全部子孙备忘录全部关联到该 Todo(一对多)

## 改动

### `lib/services/task_memo_service.dart`(核心)

- 构造函数新增两个依赖:`SubTaskRepository` + `MemoService`(按 `main.dart` 装配顺序,memoService 先于 taskMemoService 创建,可直接引用)
- 新增公开方法 `collectSubtree(Memo memo)`:前序 DFS 递归收集整棵子树(父先于子),**跳过已删除节点及其整棵子树**(`getChildren` 的 SQL 只过滤 `archived_at`,不过滤 `deleted_at`,需在代码里过滤)
- 新增私有方法 `_createSubTaskTree(Memo memo, int taskId, int? parentSubTaskId)`:递归将子孙备忘录转 SubTask,先父后子插入(SubTask 需要父 id);标题取 `extractTaskTitles` 首个,空则回退 `content.trim()`
- **层级映射**:父 memo(level 0)→ Task;子 memo(level n ≥ 1)→ SubTask `level = n - 1`;顶层子 memo 的 SubTask `parent_id = null` 直接挂 Task 下,更深层挂到父 SubTask 的 id
- `createTaskFromMemo`:生成 Task + link 当前 memo(现状)→ 追加 `_createSubTaskTree(memo, id, null)`
- `createTasksFromMemo`:先 `collectSubtree`,有子级 → 复用层级路径返回 `[task]`;无子级 → 保持按行拆
- `linkTaskToMemo`:`collectSubtree` 后逐个 link,签名不变

### `lib/screens/memo_screen.dart`(UI)

- `_convertToTodo`:调用前 `collectSubtree` 计数,SnackBar 动态文案("已生成 1 个 Todo 及 N 个子任务…",N=0 回退原文案)
- `_generateTodos`:预览对话框前先收集子树;有子级时对话框改为提示"该备忘录含 N 个子备忘录,将整体转成 1 个 Todo + 子任务树,不再按行拆分";无子级时保持行列表预览
- `_linkExistingTodo`:SnackBar 动态文案("Todo 与备忘录及 N 个子备忘录已关联")
- 补 `mounted` 检查(collectSubtree 是新增的 async gap)

### `lib/main.dart`(DI)

`TaskMemoService` 实例化处传入 `subTaskRepo`(已存在)与 `memoService`(已存在)。

### 测试(构造参数同步)

- `test/todo_arrangement_test.dart` / `test/mobile_layout_test.dart`:三处 `TaskMemoService(...)` 补 `SubTaskRepository(db)` + `MemoService(...)`,并补 import

## 数据模型

**无 DB 迁移、不改表结构**。SubTask.toMap 自带 sync_id/revision/updated_at,insert 直接入库;`task_memo_links.link()` 带同步字段 + `ConflictAlgorithm.ignore`(重复点击幂等);`onChanged` 触发 syncCoordinator 自动同步。

## 验收

1. 建父 memo"英语六级650分" + 2 层子 memo → 右键"转为 Todo" → Todo 详情页出现完整 SubTask 树,层级与备忘录一致
2. 同一条用"按行生成" → 预览提示整体转换,生成 1 Todo + 子树
3. 建无子级、多行 memo → "按行生成"仍按行拆多个平铺 Todo
4. "关联已有 Todo" → 反查该 Todo 的关联备忘录含父 + 全部子 memo
5. 重启应用触发 sync 后检查 Supabase 数据一致
