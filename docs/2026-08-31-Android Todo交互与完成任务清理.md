# Android Todo 交互与完成任务清理

> 日期：2026-08-31 · 数据库版本：v20（无迁移）

## 一、需求审查与方案

- 加号是新增任务，删除是移除任务，功能本身不重复；实际重复来自多选底栏与单项滑动/菜单都直接展示删除。
- Android 长按后进入多选，底栏改为“取消多选 + 完成 + 更多”；批量删除收进“更多”，单项删除仍保留在滑动/操作菜单。
- 列表和安排的已完成区域默认收起；空区域直接不渲染，减少纵向占用。清空操作必须确认，并复用软删除进入最近删除，保留恢复机会。
- 安排任务完成后按 `completed_at` 计算 7×24 小时；仅安排模式任务超过期限后自动硬删除。普通列表完成任务不受影响。

## 二、已完成内容

### 1. Android 长按选择

- 长按任务正文继续进入多选，不与拖拽柄抢手势。
- 多选底栏显示 `取消多选`，可立即清除选择状态。
- 批量删除改为“更多 → 删除所选任务”，避免与单项删除入口重复占据空间。
- 批量删除使用一次事务软删除，进入最近删除并可恢复。

### 2. 已完成区域减负

- Todo 列表的已完成区域继续默认收起，并增加“清空列表已完成任务”。
- 安排视图的已完成区域在数量为 0 时完全不渲染；有任务时增加“清空安排已完成任务”。
- 清空前显示数量和恢复期限，确认后统一软删除；不会绕过 7 天自动硬删除规则。

### 3. 安排任务 7 天生命周期

- `TaskRepository.purgeExpiredCompletedArranged` 查询 `completed_at` 超过 7 天且模式为 `plan_now/plan_next/plan_later` 的任务。
- 自动清理同时删除 subtasks、task_memo_links 和 tasks，数据库触发器继续生成同步删除事件。
- 清理在 Todo 加载任务时执行；任务完成后的 7 天内仍保留在安排的已完成区域。
- 原有最近删除 15 天清理机制保持不变；普通列表完成任务不会被新规则清理。

## 三、架构

UI：`todo_screen.dart`、`flow_screen.dart`
→ Service：`TaskService.softDeleteTasks`、`purgeExpiredCompletedArranged`
→ Repository：事务软删除、过期安排任务硬删除
→ Database：复用 v20 tasks/subtasks/task_memo_links 和既有同步触发器。

## 四、维护与风险

- 不要把清空已完成改成无确认硬删除；恢复入口依赖现有最近删除逻辑。
- 修改 7 天规则时只调整 Repository 查询和测试时钟，不要改数据库版本或直接删除用户数据库。
- 若任务完成后被重新打开，`completed_at` 清空，7 天计时重新开始。
- 该规则按本机 Todo 加载触发；长期不打开应用时不会在后台主动执行清理。
