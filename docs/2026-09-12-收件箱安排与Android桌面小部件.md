# 收件箱、安排与 Android 桌面小部件

> 日期：2026-09-12  
> 数据库：v20，不迁移

## 已完成内容

- Todo 一级入口改为“列表 / 安排”，安排内保留“阶段 / 本周”。
- 收件箱统一显示未安排任务、所有已完成任务和最近删除；移除“今天 / 未来七天”入口，保留精灵窝。
- 阶段与本周只展示未完成任务，底部“已完成 · N”跳回收件箱，不维护两套完成列表。
- 阶段三组恢复底部“＋ 同时任务”；本周每个展开日期使用“＋ 添加到今天/周几”。快捷添加仅填写名称并自动绑定目标。
- 安排模式不显示右下角全局悬浮加号；列表模式仍保留。
- 本周默认仅显示今天和有任务日期，其余日期收进“其余 N 天”，并加入上一周 / 本周 / 下一周导航。
- Android 新增“现在”和“本周”两个主屏幕小部件，面向手机和平板：列表可滚动、标题加号快捷添加、任务与一级子任务可直接完成、进度显示、单任务展开、编辑、软删除和阶段移动；不提供桌面排序。

## 当前架构

- Flutter 界面仍经 `TaskService → Repository → SQLite` 写入。
- Android 小部件使用原生 `RemoteViews`，直接访问同一应用沙盒内的 `todo_list.db`。
- 原生修改同步增加 `revision` 和 `updated_at`；数据库已有触发器会把变化写入 outbox。
- Flutter 每次任务重载通知小部件刷新；从小部件返回应用时，Todo 页面在生命周期恢复时重新读取数据库。
- “本周”由 `due_date` 派生，“阶段”由 `task_mode` 派生，不复制任务。

### Kotlin Release 编译修复

- 小花先生侧构建已进入 `compileReleaseKotlin`，说明此前 Gradle 回环阻塞已解除。
- `WidgetTaskStore.kt` 四处 SQLite `execSQL` 参数混合 `String`、`Long` 与可空 `String`，Kotlin 无法稳定推断 `arrayOf` 的统一类型。
- 四处统一改为 `arrayOf<Any?>(...)`，仅明确 Android SQLite 所需的绑定参数类型，不改变 SQL、数据或同步行为。
- 修复后 APK 编译由小花先生侧重新执行确认。

## 潜在问题

- Android Launcher 对集合小部件、嵌套子任务和刷新频率的实现存在厂商差异，必须至少验收一台手机和一台平板/大屏模拟器。
- 小部件直接写库依赖应用已经至少启动一次完成数据库初始化；未初始化时会引导打开应用。
- 小部件只展开一级子任务；深层子任务仍在应用详情内维护。

## 下一步建议

1. 修复 Gradle 回环连接并生成 Debug/Release APK。
2. 在手机与平板分别添加“现在”“本周”，验证滚动、添加、主/子任务勾选、单项展开、编辑、删除和阶段移动。
3. 验证小部件操作后应用回前台即时刷新，以及登录同步后另一端收到变化。
