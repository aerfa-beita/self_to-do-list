# 收件箱归属与 Android 小部件加载修复

## 问题与判断

- 用户截图显示 Android 桌面提示“加载窗口小部件时出现问题”，两个小部件均无法显示。这是桌面宿主加载失败，不是无任务空态。
- 应用最低支持 Android API 24，但原生集合行 `widget_task_item.xml` 和 `widget_subtask_item.xml` 使用 `CheckBox`。Android 官方 `RemoteViews` 仅从 API 31 起支持 `CheckBox`；这是可确认的兼容缺陷。截图未提供 Android 版本与 logcat，因此不能断言它就是该设备上唯一的失败原因。
- 先前把“已完成 · N”作为安排页底部捷径，仍然占据安排页面。用户明确要求“已完成”和“最近删除”只归属收件箱。

## 修改

- 小部件任务及一级子任务的勾选入口改为所有目标 API 均支持的 `ImageButton`；用勾选/未勾选矢量图标保持原有方框外观，点击仍发送原有完成事件。
- 小部件子任务行触控区域调整为 48dp。
- 阶段、本周视图移除“已完成 · N”捷径；收件箱继续显示全局“已完成”和“最近删除”，不改变记录存储或恢复逻辑。

## 架构与维护

- 小部件布局在 `android/app/src/main/res/layout/widget_task_item.xml`、`widget_subtask_item.xml`；图标在 `res/drawable/ic_widget_check_*.xml`；状态绑定在 `TaskWidgetService.kt`。
- 应用视图归属在 `lib/screens/flow_screen.dart`、`todo_screen.dart`。任务仍是同一 SQLite 记录，数据库版本与同步协议不变。
- 后续小部件兼容问题先取桌面宿主与本应用的 logcat，再针对异常堆栈修复，不凭通用错误提示盲改。
