# Android“安排优先”整体改版

> 日期：2026-09-15
> 数据库：v21 → v22
> 主要平台：Android；Windows 同步数据、桌面菜单与 Release 构建同步适配

## 已完成内容

### 导航与信息架构

- 手机底部导航收敛为“备忘录 / 安排”，任务模块首次进入默认打开本周。
- 安排顶部只保留一层“本周 / 阶段 / 收件箱”，移除固定 `Todo List` 标题和重复的“列表 / 安排”“阶段 / 本周”双层切换。
- 重开应用会恢复上次根模块、任务一级页面及其智能视图；恢复本周时始终定位设备当前周，不恢复详情页、搜索词和周偏移。
- 备忘录顶部改为当前分类、搜索、同步和更多，删除重复的大号“备忘录”标题。

### 任务归属与状态视图

- 一条任务可同时拥有阶段和日期，阶段、本周、收件箱继续共用同一条记录，不创建副本。
- “已安排”定义为拥有阶段或日期的未完成任务；任务移到阶段或本周后立即离开收件箱。
- 完成与删除是全局状态，但通过 `completed_scope`、`deleted_scope` 记录操作来源 `inbox/stage/week`。
- 收件箱智能视图固定为“收件箱 / 已安排 / 已完成 / 最近删除 / 精灵窝”；阶段和本周固定为“未完成 / 已完成 / 最近删除”。各视图严格互斥。
- “已安排”是平铺管理页，只提供详情、编辑、调整阶段和日期，不显示完成与删除入口。
- 从收件箱恢复会清除阶段、日期和提醒；从阶段恢复保留原阶段；从本周恢复到设备当前周相同星期几并保留原阶段。
- 从最近删除恢复时，原本已完成的任务回到原来源的已完成视图，不重新安排提醒；未完成任务回到对应活动视图。

### 排序与菜单

- Android 收件箱长按整张任务卡排序；长按不再进入多选，多选通过“筛选与统计”中的明确“选择”按钮进入。
- 收件箱三点菜单为“编辑 / 移到阶段 / 移到本周 / 分隔线 / 删除”，每项使用 20dp 线性图标和至少 48dp 菜单行。
- Android 的阶段与星期选择使用底部选择面板；Windows 使用任务旁锚定二级菜单。
- 阶段继续长按组内排序；跨阶段、同步今日和删除通过三点菜单。本周继续长按同日排序，“调整日期”负责跨日拖动。
- 过去日期没有未完成任务时默认收起；存在未完成任务时自动展开。空日期固定显示标题但不显示 `0`。
- 列表滑动完成保持移除，仅保留向左滑出操作，降低误触。

### 备忘录与原生小部件

- 备忘录卡片三点菜单统一为“编辑 / 置顶 / 归档 / 转为任务 / 关联任务 / 分隔线 / 删除”，继续保持备忘录数据和任务数据分离。
- Android 原生小部件写入完成、删除状态时同步记录 `stage/week` 来源；旧数据库没有 v22 字段时保持兼容。
- 小部件、Flutter、JSON 与 Supabase 继续共享同一条任务记录。

## 当前架构

- `Task.taskMode` 表示阶段，`Task.dueDate` 表示安排日期，`completedScope` 与 `deletedScope` 只表示状态操作来源。
- `sort_order` 服务于列表和阶段，`week_sort_order` 服务于本周同日排序。
- `TodoScreen` 负责一级页面、智能视图、来源过滤、恢复规则、提醒取消与重排。
- `TaskArrangementView` 负责阶段/本周布局、分组排序、日期折叠、跨日拖动和任务菜单。
- `TaskRepository` 与 `TaskService` 写入全局完成/删除状态及来源；`SyncEngine` 兼容缺少来源字段的旧云 payload。
- Android `WidgetTaskStore` 运行时检测 v22 字段，因此新旧数据库都能被桌面小部件读取。

## 数据迁移与维护

- `DatabaseProvider` 当前版本为 22。首次打开 v21 文件库前创建 `.pre-v22` 数据库备份；WAL/SHM 存在时同步复制。
- v22 增加 `completed_scope`、`deleted_scope`。旧记录按“有阶段优先归阶段，其次有日期归本周，否则归收件箱”推断来源。
- 旧 JSON、旧云 payload 缺少字段时使用同一推断规则；非法来源值归一化为空后重新推断。
- 新增任务状态来源时，必须同时检查模型、SQLite 建表/迁移、Repository、Service、JSON、SyncEngine 和 Kotlin 小部件。
- 页面位置属于设备本地偏好，只写 `settings`，不进入云同步。

## 潜在问题

- Android Kotlin 小部件改动已做源码适配，但仍需成功完成 Gradle 编译和真机 Launcher 验收。
- 手机顶部三段导航、底部二级选择面板和长按拖动已经组件测试覆盖，仍需真机确认字体缩放、系统安全区和触摸手感。
- 列表仍逐条读取子任务进度并在刷新时处理提醒，任务量较大时可能出现延迟。
- 历史文档中的“已完成只归收件箱”“列表 / 安排双层导航”已被本方案替代，维护时以本文件和 `DESIGN.md` 为准。

## 下一步优化建议

1. 在普通 PowerShell 或 Android Studio 执行 `flutter build apk --release`，确认生成时间后侧装真机。
2. 真机集中验收底部导航、顶部三页、来源已完成/最近删除、长按排序、二级移动面板、页面恢复和两个桌面小部件。
3. 优先增加“逾期未完成集中处理”，提供旧周遗留任务汇总和批量移到今天。
4. 后续评估常用任务模板、批量读取子任务进度和只在相关字段变化时更新提醒。

## 可复用经验

- 同一实体跨多个业务视图时，完成和删除可以保持全局，但必须单独记录操作来源，才能提供可解释的归档入口和恢复路径。
- “已安排”适合作为管理集合，不适合作为第三个执行入口；限制完成和删除能减少用户对任务归属的误判。
- 手势应只承担一个高频动作。长按排序后，多选必须改为可见按钮，否则会产生模式冲突。
- 构建目录里的旧 APK 不能证明本次改动已构建；必须核对时间、安装包版本和实际设备截图。
