# Android 签名校验空安全编译修复

> 日期：2026-09-16
> 触发命令：`flutter build apk --release --no-pub`

## 问题

Android Release 在 `:app:compileReleaseKotlin` 阶段失败：

```text
MainActivity.kt:242:26 Only safe (?.) or non-null asserted (!!.) calls are allowed
on a nullable receiver of type 'Array<(out) Signature!>?'.
```

`PackageInfo.signatures` 是旧 Android API 的平台类型，Kotlin 会把它视为可能为空。原实现直接调用 `map`，因此 Release 编译器拒绝通过。字体 tree-shaking 提示与失败无关。

## 修复

- `signerDigests()` 对可空签名数组使用安全调用；读取不到签名时返回空集合。
- APK 校验同时检查已安装应用与下载 APK 的签名集合：任一为空或二者不一致都拒绝安装。
- 保留 Android 9 及以上的 `SigningInfo.apkContentsSigners` 和旧系统的 `PackageInfo.signatures` 双路径，不改变最低 Android 版本。

## 验证

- Kotlin 报错行已改为可空安全调用，原始编译错误已消除于源码层。
- Codex 环境重新执行相同 Release 构建时，在 Kotlin 编译前被既有 `Unable to establish loopback connection` 环境故障拦截，因此没有宣称 APK 构建成功。
- 普通 PowerShell / Android Studio 需重新执行原命令完成最终编译验证。

## 维护规则

- Android 平台类型不能按非空 Kotlin 类型使用，尤其是 `PackageInfo` 的旧签名 API。
- 签名、摘要、包名和版本等安全校验失败时必须关闭安装路径；缺失值不能按相等处理。
