# 精灵窝退场与安排优先导航

> 日期：2026-09-16
> 数据库：v22 → v23

## 已完成

- 手机和桌面主导航统一为“安排｜备忘录”，首次启动直接进入安排的本周页。
- Android 根页面记忆改用语义值 `arrange/memo`；旧数字设置按旧顺序迁移，避免导航换序后恢复错误页面。
- 收件箱移除精灵窝入口，创建任务不再写入暂存状态。
- 今日负荷超限时只提供“改到明天／仍然创建”，不再自动搬运或隐藏任务。
- DB v23 打开 v22 数据库前创建 `.pre-v23` 备份，并清空 `companion_stashed_at`：
  - 无阶段、无日期的任务回到收件箱。
  - 原有阶段或日期保持不变，继续出现在对应安排位置。
- Android 原生小部件和今日负荷统计不再排除旧暂存标记，避免旧云端或旧 JSON 数据再次变成不可见任务。
- 桌面二级移动菜单等待一级菜单关闭后再打开；无效的整卡锚点回退到安全位置，避免菜单超出窗口或被遮挡。

## 当前架构

- `tasks.companion_stashed_at` 暂时保留在模型、JSON 和同步协议中，只用于兼容旧客户端，不再参与新界面分流。
- 活动任务只按阶段 `task_mode` 和日期 `due_date` 判断归属。
- Android 页面位置由两个本机设置保存：
  - `android_last_root_page`：`arrange/memo`。
  - `android_last_todo_page`：本周、阶段、收件箱及各自状态视图。

## 维护方式

- 后续新增根导航页时继续保存语义名称，禁止恢复数字下标。
- 等所有仍在使用的旧版本退出后，再单独评估删除 `companion_stashed_at`；删除前必须同时升级 Supabase 表、JSON 导入和 Android 小部件 SQL。
- 发布 v23 前保留 `.pre-v23` 数据库备份，并核对迁移前后任务总数、阶段和日期。

## 验证

- 专项测试：21/21 通过，覆盖 v22→v23 备份、三类旧暂存任务释放、语义页面迁移和安排优先导航。
- 完整 Flutter 测试：70/70 通过。
- `flutter analyze`：无编译错误；仍有项目既有 17 条 info/warning，本阶段未新增。
- Windows Release、Android Release 和真机截图留到安排页视觉方案确认并实现后统一验收。

## 潜在问题与下一步

- 旧客户端仍可能把非空 `companion_stashed_at` 同步回来；v23 会正常显示该任务，但不会主动回写清空，待后续同步协议清理。
- 小精灵仍保留现有组件和历史搬运动画代码，但当前产品流程不会触发精灵窝动作；动画重做属于后续独立批次。
- 安排页两张方案图已经生成，视觉方向确认前不修改 `DESIGN.md` 或安排页布局代码。
