# Android 全屏通知恢复

> 日期：2026-09-18  
> 发布版本：1.3.1+7 · DB v23

## 问题与根因

- Android Release APK 中缺少 `stride_reminder` 原始音频资源。
- 全屏任务提醒和今日巡检把该资源作为通知通道声音传给系统，插件因此返回 `invalid_sound`，提醒没有进入系统排程。
- 根任务原有提醒也已复用全屏通道，所以资源异常会表现为“新全屏提醒和原通知同时消失”。

## 修复

- 全屏提醒切换到新通道 `stride_full_screen_reminders_default_sound_v3`。
- 通道使用系统默认声音，不再依赖 `RawResourceAndroidNotificationSound`。
- 根任务到点、今日巡检和“稍后 10 分钟”统一复用同一套 Android 全屏通知参数。
- 保留 `Importance.max`、闹钟类别、公开锁屏可见性和 `fullScreenIntent`；Android 14+ 未授予特殊权限时仍由系统降级为高优先级横幅。
- 自定义 Stride 铃声文件暂时保留，但当前通知链不引用它，后续单独处理资源保留和真机试听。

## 验证

- 提醒专项：7/7 通过。
- 完整 Flutter 回归：89/89 通过。
- 静态检查：通知改动文件无问题；全项目保留原有 17 项提示，没有新增问题。
- Android 真机与 Release APK 尚需重新构建后验收，旧 `1.3.0+6` APK 仍包含该故障，不能继续分发。

## 维护与边界

- Android 通知通道属性创建后不可修改；声音策略变化必须使用新的通道 ID。
- 通知可靠性优先于自定义声音。自定义资源再次启用前，必须检查最终 Release APK，而不能只检查源码和 Gradle 中间产物。
- 首次安装没有页面记忆时，安排内容默认使用 `active`，与顶部默认“本周”保持一致；已有页面记忆仍按原设置恢复。
